## Riproduzione

Ambiente verificato: JDK 21, SDK Android 36, build-tools 36.1.0, Gradle 8.14.3.
Da un checkout isolato del codice indicato, con la versione Android sopra riportata:

```powershell
cd frontend
npm ci --no-audit --no-fund
$env:CI='true'
npm run test:ci -- --runInBand
npm run typecheck
npm run lint
$env:REACT_APP_API_URL='https://scommese-sportive-backend.hostless.app/api'
$env:GENERATE_SOURCEMAP='false'
npm run mobile:sync
$env:JAVA_HOME='C:/Program Files/Eclipse Adoptium/jdk-21.0.12.101-hotspot'
$env:ANDROID_HOME='C:/Users/ACER/AppData/Local/Android/Sdk'
cd android
./gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest --console=plain
```

Con un emulatore di test dedicato avviato, installare l'APK e l'APK strumentale in
`app/build/outputs/apk/`, quindi eseguire:

```text
adb -s <emulatore-di-test> shell am instrument -w it.footpredictor.personal.test/androidx.test.runner.AndroidJUnitRunner
```

La ricompilazione richiede lo stesso keystore debug per conservare il certificato.
Non è promessa identità binaria tra build su macchine diverse.

## Limiti e installazione

Non sono verificati telefono fisico, altre versioni Android, login autenticato e durata
della sessione. Nessuna password è stata inserita nell'emulatore e nessuna puntata è stata
creata durante questi controlli. Sono presenti avvisi preesistenti di deprecazione nelle
dipendenze, nei test React e in Gradle; non hanno impedito i controlli sopra elencati.

Aprire il link APK dal telefono e autorizzare l'installazione per il browser se richiesto.
Se Android segnala firma incompatibile, non disinstallare alla cieca: la firma del telefono
non è stata controllata. L'aggiornamento è stato provato soltanto dal precedente APK debug
locale; una versione firmata diversamente richiede il suo keystore originale.
