## Build e verifiche

Build da worktree Git isolato alla sorgente indicata, `npm ci` e dipendenze del
lockfile. Escluse le modifiche locali estranee a `walletApi.ts` e relativo test.
`CI=true`, `REACT_APP_API_URL` come sopra, `GENERATE_SOURCEMAP=false`;
`npm run mobile:sync`; JDK 21, Android SDK e firma debug già presenti.
Non sono state create nuove chiavi. Comandi Gradle:

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest --console=plain
```

- Frontend pulito: **34 suite / 295 test**, typecheck, lint e build passati.
- Backend della stessa sorgente: CI Linux **1.233 passati, zero falliti, uno
  opzionale saltato**; le 7 regressioni A proteggono 36 sorgenti e 6 scenari golden.
  Il successivo commit di soli test `b98147bb` verifica anche quei sei scenari A
  prima e dopo il calcolo C nello stesso processo (8/8 con la regressione base),
  senza cambiare i sorgenti applicativi inclusi nell'APK.
  Anche la [CI aggiuntiva](https://github.com/Ivandragon003/scommeseSportive/actions/runs/41219156825)
  è passata: 1.234 test riusciti, zero falliti, uno opzionale saltato.
- Gradle: 103 task riusciti, un test unitario dimostrativo e **2 test strumentali**
  passati sull'emulatore QA. Il test dimostrativo non certifica il modello.
- APK: firma v2 verificata, tutti i **19 asset** coincidenti byte per byte con la
  build web isolata, senza asset obsoleti aggiuntivi salvo i due file Cordova
  generati. Nessun env, keystore o source map; scansione Gitleaks senza rilievi.
- Installazione `adb install -r` dalla 1.1.5 alla 1.1.6 riuscita; marker privato
  nell'archivio locale preservato. Avvio a freddo verificato attraverso DOM login
  effettivamente pronto, bundle `main.491d309b.js` e screenshot; nessun errore
  fatale o JavaScript osservato nel processo app. Un semplice `am start` o dump
  UI vuoto non è stato usato come prova sufficiente.
- Browser separato con API simulate: **15 scenari passati**, desktop e mobile,
  più controllo delle risposte tardive. Nessun endpoint contabile richiesto.

Le prove native non accedono con la password dell'utente e non interrogano
provider reali. Non certificano telefono fisico/ARM o flusso A/C autenticato
sul dispositivo reale. La firma release originale resta assente; una firma
diversa sul telefono può impedire l'aggiornamento e non va risolta disinstallando
alla cieca. L'emulatore e il forward QA sono stati fermati/rimossi dopo la prova.
